Purpose: give Larissa a compact human-event-organizer review sheet before volunteer outreach. This is a summary of `program/run-of-show-v1.md`, `program/interactive-stations-v1.md`, `ops/volunteer-roster-working-v0.md`, and `logistics/device-and-av-plan-v0.md`.

## The core ask for Larissa's feedback

Please sanity-check:
1. Are these activities feasible in one Theater Gallery room with ~45–60 comfortable active participants and up to ~70–80 at the outer edge?
2. Is the volunteer ask realistic for a Saturday-night SF event?
3. Which stations should be simplified first if the room, helper count, or setup window is tighter than expected?

## Activity scope in plain language

The event has a phased flow, not five stations running all night from doors-open:

1. **Doors / check-in / name tags** — simple welcome table, Partiful list/backup sheet, door prompt cards.
2. **Welcome + demos** — Larissa hosts; attendees mostly sit/stand and watch one shared screen.
3. **Human×AI Field Day stations** — stations open after demos; attendees rotate casually. No one needs a laptop at every station.
4. **Artifact harvest** — MC gathers favorite outputs/headlines/scores and reads a few back to the room.
5. **Open social + cleanup** — food/drinks/social time, then restore room.

## Five station concepts, with staffing reality

| Station | What attendees do | Human support needed | Simplest mode |
|---|---|---|---|
| Prompt Relay Race | Take turns improving one prompt and compare the output. | Helpful floater explains first round; optional phone/tablet/device. | Printed cards + worksheet; facilitator/phone optional. |
| Event-in-a-Box | Draw audience/venue/twist cards and co-design a tiny future event. | Mostly self-serve; floater helps people start. | Card decks + pitch cards, no device required. |
| Bug Triage Theater | Role-play a release team deciding whether a weird bug ships. | Best with occasional facilitator energy; can still be card-led. | Role cards + incident cards + APPROVED/BLOCKED decision. |
| Future Headline Wall | Write speculative future headlines and post them by mood/category. | Very self-serve; good for overflow and late arrivals. | Cards + freestanding board/easel/tri-fold. |
| Village Arcade Booth | Play agent-built projects and write high-score cards. | Only if a supervised device/helper exists. | QR wall + attendees use phones; high-score cards stay physical. |

## Volunteer roles to recruit

### Must-have beyond Larissa if possible

1. **Demo laptop driver / projection operator**
   - Time: ideally 6:30–8:15 PM.
   - Job: test projector/audio, open slides/links, drive the shared screen during welcome/demos.
   - Important: if Demo 2 is live, this exact projection laptop must be signed into village chat and showing only `#showcase-live`, never `#best` or private scrollback.

2. **Check-in helper**
   - Time: 6:45–7:30 PM.
   - Job: greet, name tags, RSVP/backup list, point people to the room.
   - Can become a station floater after check-in rush.

3. **1–2 station floaters**
   - Time: 8:05–9:10 PM.
   - Job: help guests understand station rules, refill cards/markers, encourage rotation, watch for confusion.
   - No AI expertise needed.

### Nice-to-have

4. **Arcade helper / supervised device owner**
   - Only needed if we run a dedicated Arcade laptop/tablet.
   - If unavailable, use QR/phone mode.

5. **Room-flip / reset hands**
   - Time: roughly 8:05–8:15 and 9:45–10:20.
   - Job: move a few chairs, tidy station tables, restore space with Larissa.
   - Can be the same people as floaters/check-in.

## Minimum viable event if planning-fallacy risk shows up

If setup time, AV, venue answers, or helper count are worse than expected, protect this smaller event rather than trying to run every built asset:

1. Doors/check-in and a clear welcome.
2. One reliable demo path: live clean-room Demo 2 only if already confirmed/tested; otherwise the rehearsal recording.
3. Two or three self-serve stations with strong signs/cards.
4. Snacks/drinks/water, a visible schedule, and a clean close/breakdown.

The full five-station plan is upside, not a promise we should defend at the expense of room flow or reliability.

## Staffing tiers

| Tier | On-site humans | What changes |
|---|---:|---|
| Comfortable | 6–8 including Larissa | MC, demo driver, check-in, 2–3 floaters, Arcade/helper, breakdown. All 5 stations feel supported. |
| Lean | 3–4 including Larissa | MC, demo driver, 1–2 roamers. Stations run mostly self-serve; Arcade likely QR/phone mode. |
| Bare minimum | Larissa + 1 | Keep welcome/demos simple, cut optional Demo 4 first, run only the clearest stations self-serve, make Arcade QR-only. |

## Recommended simplification order

If Larissa thinks the plan is too much, simplify in this order:

1. **Make Village Arcade QR/phone-only** unless a supervised device/helper is easy.
2. **Make Future Headline Wall fully self-serve**; it is the best overflow activity.
3. **Combine Prompt Relay + Event-in-a-Box under one floater** instead of separate hosts.
4. **Run Bug Triage as a scheduled mini-round** rather than an always-on station.
5. **Cut optional Demo 4** before cutting the core welcome, Demo 2, or stations.
6. If still too much, reduce to **3 strongest stations**: Event-in-a-Box, Future Headline Wall, Village Arcade QR wall.
